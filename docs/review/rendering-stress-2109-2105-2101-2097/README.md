# Four isolated rendering workload labs

Exact issue IDs, source heads, actual parents and branches are in source.json. All four current issues were inspected in full, with comments, timeline/cross-references, actual main-branch source, contribution rules and all open PRs. No previous claimant, assignee, matching PR or requested stress API/files existed. Existing benchmark-suite modules time CPU operations; visualizers do not provide the requested DOM/frame-jitter lab. Actual bot assignments preceded new branches and coding. Each PR adds only its four explicitly required isolated files, retaining all common files.

Each engine measures real animation-frame intervals while updating 64 real DOM nodes and forcing geometry reads. It reports independently calculated jitter, timed layout work, optional approximate Chromium JS heap and a documented bounded workload index. Heap does not enter that score. Layout timing is a rendering proxy rather than direct GPU paint measurement; the index describes this local workload, not overall hardware quality. Samples remain local.

Ten meaningful Node cases per module, scoped oxlint and all four normal Node22 builds pass. All eight actual Vite development/production browser reports pass native keyboard start,61 independently observed callbacks for60 measured intervals and60 forced layout reads, independent FPS/jitter math, report interaction, invalid input preservation, cancellation, failure/retry and node/frame cleanup. Visibility changes, unavailable heap and a layout exception are explicit fault fixtures. Normal timestamp/DOM measurements are not mocked. Desktop and320/390/760px layouts, reduced motion and zero page errors/failed resources pass. Representative desktop/mobile screenshots for all four targets were visually inspected. Recorded approximately60Hz callback cadence is an observation of the test machine, not a universal performance promise.

Reproduce with Node22, npm ci and npm run build. Start npm run dev and npm run preview on separate localhost ports. Run each module's telemetry-stress-tester.test.mjs with node --test. Invoke browser-check.mjs for each server with BASE,FOLDER,OUT,PLAYWRIGHT_MODULE and optional CHROME_PATH. The harness and source manifest are kept beside all test/build/browser logs and screenshots.
