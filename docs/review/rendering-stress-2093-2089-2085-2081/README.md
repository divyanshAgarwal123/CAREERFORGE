# Four isolated rendering workload labs

Exact source heads, actual parents and linked assignments are in source.json. Actual assignment preceded coding. Each issue was inspected in full against comments, timeline/cross-references, matching PRs, current contribution rules and source. All required dedicated stress files/APIs were absent. The existing Nonprofit benchmark already provides real rAF throughput, chunked CPU-operation latency and optional memory; it is preserved. This lab adds the still-required real DOM/geometry workload, adjacent-interval jitter, documented composite index and separate StressBenchmarkEngine API. The other existing benchmark-suite modules provide CPU-throughput percentiles and are also preserved. No common or protected source/config files change.

Each module updates64 actual DOM nodes, forces a geometry read and measures actual animation-frame intervals. It reports jitter and DOM/layout cost, optional approximate heap and a bounded documented workload index. Heap is excluded from the index and may decrease during collection. Forced layout is a rendering proxy, not direct GPU paint timing; the index describes this workload, not overall hardware quality. Data remains local.

Ten focused Node cases per module, scoped oxlint and all four normal Node22 builds pass. All eight native Vite development/production reports pass61 observed callbacks for60 intervals,60 real forced layout reads, independent FPS/jitter calculations, keyboard start/stop, reports, invalid preservation, errors/retry, cancellation and cleanup. Visibility, unsupported heap and layout exceptions are explicit fault fixtures; normal measurements are not mocked. Reduced motion and desktop/320/390/760px containment pass without page errors or failed requests. All four representative desktop/mobile screenshots were visually inspected. Recorded near60Hz callback cadence is a local observation, not a universal performance guarantee.

Reproduce using Node22, npm ci and npm run build; run each standalone telemetry-stress-tester.test.mjs with node --test. Start npm run dev and npm run preview on different localhost ports. Invoke browser-check.mjs with BASE,FOLDER,OUT,PLAYWRIGHT_MODULE and optional CHROME_PATH. Each source/mode's report, screenshots and test/build logs remain separate.
